# Белковый шеф

Выберите продукты в таблице, задайте желаемые калории и белок — приложение автоматически составит меню с **приоритетом цели по белку**, затем калорийности и остальных БЖУ на **30 дней без повторения блюд**. Норма калорий не назначается по росту, возрасту или весу: пользователь выбирает её сам.

## Как это работает

1. Таблица всех продуктов каталога: «Хочу», «Можно», «Исключить». Есть курица, индейка, кролик, говядина, свинина, рыба, молочные продукты, крупы, овощи и другие продукты. Исключение проверяется по идентификатору ингредиента, а не только по названию блюда.
2. Калории и белок: можно нажать готовую кнопку или ввести свою цифру. Жиры можно задать дополнительно; углеводы в этом случае рассчитываются как оставшиеся калории. Выбранная цель питания не меняет калорийность автоматически.
3. Число приёмов пищи, время приготовления и дополнительные ограничения. Меню подбирается под указанные цели: отклонение по белку получает больший вес в подборе, чем отклонение по калориям, жирам и углеводам. Если они недостижимы с точностью ±10%, отображаются фактические значения и предупреждение.

В каталоге 578 рецептов и сочетаний продуктов. За месяц получается 90–150 разных блюд. Ингредиенты могут повторяться. Кнопка «Другой вариант меню» предлагает альтернативный месяц; уникальность проверяется внутри каждого варианта. При нехватке подходящих рецептов неполный месяц не выдаётся как готовый.

## Расчёт КБЖУ

Все рецепты используют одну таблицу `src/foods.js` с **средними справочными БЖУ на 100 г**. Отдельных заранее заданных итогов КБЖУ нет. Массы и идентификаторы продуктов находятся в `recipe.components`; итог рассчитывается в `src/nutrition.js`.

Формула каждого ингредиента: масса в граммах × значение на 100 г ÷ 100. Калории рассчитываются по 4/9/4 (белки/жиры/углеводы). Масса мяса и рыбы — до готовки, крупы — сухие, бобовые — варёные. Эти состояния явно указаны. Результаты округляются до 0,1 только после расчёта; сумма округлённых строк может незначительно отличаться от итога. Масса выбранной порции сначала округляется до 0,1 г, затем из неё рассчитывается КБЖУ, чтобы таблица и итог использовали одинаковое количество продуктов.

Пример: 55 г овсяных хлопьев + 170 г творога 5% + 100 г персика дают **37,1 г белка** по текущему справочнику. 74,1 г белка — двойная порция: 110 г хлопьев, 340 г творога и 200 г персика. Размер порции выделен отдельно, а вклад всех продуктов виден в таблице внутри рецепта.

Значения конкретной марки или отруба могут отличаться от справочных. Для расчёта по упаковке соответствующие значения на 100 г нужно заменить в `src/foods.js`. Формулы корректны, но справочник не гарантирует лабораторную точность. Аллергические фильтры не оценивают следы аллергенов — проверяйте маркировку.

Профиль, избранное и готовое меню сохраняются в браузере. Старые меню предыдущей версии расчёта не восстанавливаются как актуальные. На каждом дне видны суммарные КБЖУ; весь месяц с массами и рецептами можно скачать в TXT.

## Запуск

Node.js 24.5+ (проверен 24.19).

```sh
cd /workspace/belkovy-shef-
npm ci
npm run dev -- --port 5173 --strictPort
```

Подбор меню работает локально без базы данных и API-ключа.

```sh
npm test
npm run build
npm start
```

Production-сервер отдаёт `dist/`; порт по умолчанию 5173, меняется через `PORT`. Серверные команды используют HTTPS-прокси среды. Тесты проверяют расчёт по массам всех рецептов и размерам порций, пример с творогом и овсянкой, дневные итоги, исключения по продуктам, уникальность месяца и обработку невозможных ограничений.

## Файл для просмотра

```sh
npm run build
npm run export
```

Создаётся `/workspace/belkovy-shef-preview.html`. Скачайте и откройте его в браузере: таблица продуктов, подбор меню и каталог работают без сервера.

## Мобильная версия и ваши изменения

Приложение подготовлено для установки через Safari на iPhone: манифест, иконки и service worker для работы без сети. Для установки с иконкой нужна публикация сайта по HTTPS. Обычный просмотр скачанного HTML в «Файлах» на iPhone не запускает приложение. Подробности — [PHONE.md](PHONE.md).

`npm run build` собирает сайт, файл `dist/belkovy-shef.html` и версионируемый офлайн-кэш. `npm run export` дополнительно создаёт рядом с проектом `belkovy-shef-mobile.html`, `belkovy-shef-source.zip` (редактируемые исходники) и `belkovy-shef-site.zip` (сайт для HTTPS-хостинга), сохраняя прежний файл preview. Зависимости, Git-метаданные, секреты и `.env.local` в архив исходников не включаются.

Вы можете дорабатывать исходный код и переносить приложение; инструкция и сведения о сторонних лицензиях — [OWNER.md](OWNER.md). Workflow `.github/workflows/pages.yml` публикует изменения из `main` после включения GitHub Pages с источником GitHub Actions. GitHub Pages отдаёт статический сайт и не запускает серверное распознавание фото.

## Подготовленный серверный API ИИ

Серверный модуль `server/assistant.js` сохранён для интеграции свободного диалога. Основной интерфейс использует выбор кнопками и не требует ввода текста или подключения ИИ. API требует серверного секрета `CHEF_AI_KEY` и HTTPS-доступа к `api.openai.com`; модель по умолчанию `gpt-4.1-mini`. Не храните ключ в клиентских переменных `VITE_*`, отслеживаемых файлах или чате. API проверен с подставленными ответами; реальный вызов модели не проверен без ключа. При публичной интеграции платного API нужны контроль доступа и расходов.

Код интерфейса: `src/planner-ui.js`, алгоритм: `src/planner.js`, продукты: `src/foods.js`, расчёт КБЖУ: `src/nutrition.js`, рецепты: `src/recipes.js` и `src/catalog.js`.

## Фото еды и расчёт белка

Раздел «Фото еды» позволяет снять блюдо камерой телефона (`capture="environment"`, если браузер поддерживает) или загрузить JPEG/PNG/WebP. Снимок уменьшается в браузере до 1024 пикселей по длинной стороне и отправляется в OpenAI только по явному нажатию «Распознать». Приложение не сохраняет фото или историю снимков.

Сервис предлагает отдельные продукты, приблизительные массы и уровень неопределённости. Пользователь проверяет продукты, готовую массу, масло и соусы и нажимает «Подтвердить состав и рассчитать». Любое изменение состава или веса убирает устаревший результат. Продукт без соответствия справочнику требует выбора вручную, а не подменяется похожим автоматически. Можно добавить или удалить ингредиент и указать известную массу всего блюда; при несовпадении с суммой ингредиентов выводится предупреждение.

Фотокалькулятор использует ту же формулу КБЖУ, что и рецепты, но отдельные справочные значения готовых продуктов из `src/photo-foods.js`. Например, 150 г готовой курицы + 200 г варёного риса дают 51,9 г белка по этому справочнику. Сырые продукты и сухие крупы нельзя подставлять вместо готового веса. Масса по фотографии остаётся предположением — снимок не заменяет взвешивание.

`POST /api/food-photo` принимает изображение как data URL JPEG/PNG/WebP и необязательный `totalWeight`. Сервер проверяет формат, размер, источник запроса и частоту обращений; ответ модели проходит проверку. КБЖУ считаются кодом по подтверждённому составу, а не берутся из ответа модели.

Ручной выбор продуктов и расчёт работают в standalone-файле без сервера. Автораспознавание требует запущенного Node.js-сервера, рабочего `CHEF_AI_KEY` и доступа к `api.openai.com`. В текущей среде binding и переменная присутствуют, но реальная проверка получила OpenAI 401 / `invalid_api_key`. Требуется исправить существующий секрет в настройках среды и перезапустить сервер; новую дублирующую привязку создавать не нужно. Не передавайте ключ в чат. Реальное распознавание еды пока не подтверждено. API и интерфейс проверены с подставленными ответами; взаимодействие с реальной камерой зависит от устройства и браузера.

## Автоматическая случайная замена блюда

В каждом приёме пищи есть кнопка «Предложить другое блюдо». Одно нажатие сразу случайно выбирает и сохраняет подходящее новое блюдо без списка вариантов и дополнительных подтверждений. Повторное нажатие предлагает другую замену.

Белок сохраняется **в точности до отображаемых 0,1 г по справочнику** относительно заменяемого блюда. Алгоритм подбирает размер порции в пределах 0,75–2 базовых порций и проверяет КБЖУ по фактическим округлённым массам ингредиентов. Коэффициент порции показывается до четырёх знаков, массы — до 0,1 г. Это расчётные значения, а не измерение белка в реальном продукте.

В подборе сохраняются тип приёма пищи, исключённые продукты, диета, аллергенные фильтры, время готовки и отсутствие повторов во всём текущем месяце. Среди замен с тем же белком при наличии выбираются варианты в пределах ±10% от желаемых калорий за день; случайная рекомендация берётся из десяти наиболее подходящих по КБЖУ. Если таких вариантов по калориям нет, используются ближайшие доступные варианты с тем же белком, с показом фактических значений и предупреждений.

Другие блюда и порции сохраняются. Калории, жиры, углеводы и предупреждения дня пересчитываются: они могут отличаться после замены. Если подходящего нового блюда с тем же белком нет, приложение сообщает об этом и оставляет исходное меню. Замена сохраняется в браузере, восстанавливается после перезагрузки и включается в TXT.

Функция работает также в скачиваемом HTML-файле без сервера и API. Тесты проверяют равенство белка блюда и дня, разные случайные выборы, повторные замены, ограничения, уникальность и неизменность остальных приёмов пищи.
